## Common ingress contract

Both priority paths execute: CORS, decompression, body-storage cleanup, stats,
route tag `relay`, system-performance check, token auth, model request rate
limit, then distribution. Authentication precedes request parsing: missing,
malformed, unknown, exhausted, or disabled tokens produce the normalized 401
envelope, not a validation error. `Authorization: Bearer <key>` is accepted
case-insensitively and an optional `sk-` prefix is stripped before lookup.

After successful auth, distributor JSON reads string `model` and optional
`group`: invalid JSON or non-string values are 400, no model is 400, forbidden
model/group is 403, and no usable channel is 503. These stop before an
upstream call, relay output, usage log, or SSE frame.

## Authenticated priority paths

### `POST /v1/responses`

The handler validates `OpenAIResponsesRequest`, copies it, applies selected
channel mapping/conversion/disabled-field removal/parameter overrides unless
pass-through is enabled, then calls the adapter. Non-200 upstream responses
become relay errors and enter channel error processing/retry; transport errors
become 500 `DoRequestFailed` before retry policy evaluation. Successful adapter
output is JSON or SSE as supplied by the adapter, followed by text quota
post-consumption (audio quota for `gpt-4o-audio*`).

`/v1/responses/compact` is this family with a non-retriable 400 for an
unsupported channel API type; it forwards only its documented compaction fields.

### `POST /v1/chat/completions`

The handler validates `GeneralOpenAIRequest`, configures `stream_options` only
for supported streams, and applies mapping/conversion/disabled-field removal and
overrides unless pass-through is enabled. A successful upstream
`Content-Type: text/event-stream` forces streaming even if the client did not
request it. The adapter owns exact frames; normal OpenAI streams use data frames
and `data: [DONE]` when supplied/generated by the adapter. Successful completion
post-consumes text quota, except audio usage with audio ratios.

For response-compatible channels, chat uses the Responses conversion path.
Parity must consequently preserve both requested-stream and upstream-forced-SSE
behavior.

## Retry, replay, and effects

Before every upstream attempt the controller restores `Request.Body` from the
stored body, so a retry replays original bytes. It records each selected channel
in request-local `use_channel`. Channel errors retry; other errors follow the
configured retryable status policy and stop for skip-retry errors, exhausted
attempts, or specified channels. Channel-error processing runs before retry
selection.

Non-free requests pre-consume billing. A terminal relay error refunds it and may
charge a violation fee; success post-consumes actual usage and writes usage/log
effects. Channel affinity is recorded only for responses below 400. The default
oracle disables global rate limiting; if model rate limiting is enabled it may
use Valkey. Cache key names/TTLs are not inferred from the empty auth-gate
capture.
