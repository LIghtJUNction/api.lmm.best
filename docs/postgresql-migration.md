# SQLite to PostgreSQL migration contract

This document describes the auditable first slice of the migration tooling. It
does not authorize or implement a production cutover.

## Evidence and scope

The source contract was captured read-only from the validated production
backup `20260801T002129+0800`. Only `sqlite_schema`, `PRAGMA table_xinfo`,
`PRAGMA index_list`, `PRAGMA quick_check`, and row counts were queried; no row
values were printed. The table map contains exactly 34 application tables and
explicitly lists source columns, primary keys, named indexes, converters,
sequence ownership, and the verifier algorithm.

The PostgreSQL baseline was generated by running the current Go/GORM migration
against an empty native PostgreSQL 18 cluster and taking a schema-only dump.
This preserves model-derived types, defaults, constraints, partial indexes,
reserved-identifier quoting, and sequence ownership instead of guessing them.
`schema/provenance.json` records the SHA-256 of the offline SQLite backup, the
Go model/module inputs, and both checked-in migration artifacts. CI rejects an
input or artifact change until the baseline and provenance are deliberately
regenerated and reviewed.

## Commands

From `rust/`:

```bash
cargo run -p lmm-db-migrate -- manifest-validate \
  --manifest crates/lmm-db-migrate/schema/table-map.json

cargo run -p lmm-db-migrate -- postgres-catalog-validate \
  --manifest crates/lmm-db-migrate/schema/table-map.json \
  --catalog /path/to/exported-postgres-catalog.json

cargo run -p lmm-db-migrate -- inspect \
  --sqlite /path/to/offline/one-api.db \
  --manifest crates/lmm-db-migrate/schema/table-map.json \
  --report /path/to/audit/inspect.json

bash crates/lmm-db-migrate/scripts/rehearse-postgres.sh
crates/lmm-db-migrate/scripts/verify-provenance.sh
```

`inspect` opens SQLite read-only, enables `query_only`, validates the file
header and `quick_check`, detects table/column/primary-key/index drift, and
reports counts without values. Reports contain no DSN field and are published
using a same-directory temporary file, file `fsync`, atomic rename, and parent
directory `fsync`.

CI and release gates must run the PostgreSQL rehearsal on a runner with native
`initdb`, `pg_ctl`, `createdb`, and `psql`. Missing binaries are a hard failure,
not a skipped test. The rehearsal applies the baseline to an isolated cluster,
exports the live `pg_catalog`, and validates all 34 tables, 421 columns, 172
indexes, and 29 owned `id` sequences against the v2 manifest. Types,
nullability, defaults, index key order/uniqueness/predicates, and sequence
ownership/defaults are exact contract fields. It
then builds a real SQLite fixture and equivalent PostgreSQL rows containing
booleans, recursively ordered JSON, timezone-normalized timestamps, a
fixed-scale decimal, and a three-column natural primary key. Both sides are
ordered by the complete primary key and must produce the same versioned BLAKE3
table hash.

## Canonical verification

Boolean conversion accepts only SQLite integer `0`, `1`, or `NULL`. JSON is
parsed and recursively key-sorted before compact serialization. GORM datetime
strings are parsed strictly and normalized to UTC with microseconds.
`subscription_plans.price_amount` is normalized as `numeric(10,6)` without
binary floating point.

Rows use BLAKE3 over a versioned stream containing the field count and, for
every field, a type tag, unsigned big-endian byte length, and payload. This
distinguishes typed nulls, empty values, types, and field boundaries.
Tables add a separate domain/version, UTF-8 table name, row count, and framed
row hashes; row order is the declared primary-key position order.

## Remaining production gates

The next slices must implement resumable copying, target-side canonical hash
verification, sequence `setval` after copy, authenticated application canaries,
a write-freeze/catch-up protocol, rollback criteria, and the autonomous
blue/green cutover transaction. Production remains on SQLite until those gates
are implemented, independently reviewed, rehearsed on a restored backup, and
explicitly approved.
